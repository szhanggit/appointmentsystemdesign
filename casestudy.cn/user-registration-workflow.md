# 顾客端：注册与登录

**这份文档讲的是实际来预约服务的普通顾客——跟前面几份讲商家、员工、Groway 内部员工的文档完全是两个世界。顾客怎么注册一个 Groway 账号、怎么登录，是这份文档的内容。**

## 一、设计参照：studied 了同类竞品的真实界面

在设计这部分之前，团队专门研究了同类预约类 App（参考了类似 Fresha 这样的头部产品）的真实注册/登录界面，确保 Groway 顾客端的体验不是凭空设计，而是贴近顾客已经熟悉、已经习惯的操作方式——降低顾客的学习成本。

## 二、一个核心的身份理念：顾客账号是"属于顾客自己的"，不属于任何一家店

这是这份设计里一个很重要、也很容易被忽略的决定：**一个顾客的账号是全平台通用的、独立的个人身份，不依附于任何特定的连锁或门店。**

换句话说，顾客在 A 店约了一次头疗、在 B 店约了一次美甲，用的是**同一个**Groway 账号，而不是"A 店的会员"和"B 店的会员"两个互不相干的身份。顾客跟某家店之间的关系，本质上只是"一次预约交易"，不是"办了会员卡"那种归属关系。这样的设计，是为 Groway 未来做跨店推荐、顾客画像、会员积分这类更大的产品方向留出了空间——因为顾客数据天然就是打通的，不需要日后再去做一次代价高昂的数据迁移。

## 三、三种登录方式，并排给顾客自己选

顾客登录界面同时提供三种方式，地位是平等的，只是默认推荐的顺序不同：

1. **手机号 + 短信验证码**（默认、最显眼的选项）——不需要记密码，最符合国内外顾客对"手机验证码登录"的使用习惯。
2. **邮箱 + 密码**——藏在"用邮箱登录"这个次级入口后面，照顾那些更习惯传统方式的顾客。
3. **"使用 Google 登录"**——一键登录，不需要顾客自己记任何密码。

**完成注册只需要验证手机号**，邮箱地址虽然也会收集，但不要求马上验证——这是为了尽可能降低注册的门槛和步骤，先让顾客用起来，邮箱验证这类"锦上添花"的步骤可以之后再慢慢补。

一个已知的小缺口：如果顾客是用 Google 账号登录、注册时没有留手机号，那么"手机号 + 验证码"这种登录方式对这类顾客暂时不可用——这是当前版本可以接受的一个边缘情况，以后再补上"后续补充并验证手机号"的功能。

## 四、找回密码，走的是标准流程

忘记密码走的是目前所有互联网产品都在用的标准流程：填邮箱 → 收到验证码 → 验证码 + 新密码 → 完成。没有特殊设计，拿来即用，稳妥可靠。

## 五、留给未来的一个商业接口：第三方合作伙伴读取顾客数据

文档里预留了一个面向未来的能力：允许某个经过授权的第三方合作方（不是代表某一个具体顾客，而是以"合作伙伴"自己的身份）通过标准的授权方式，调用接口读取顾客相关数据。这是一个面向未来生态合作（比如跟其他商业伙伴做数据对接）的预留设计，目前还没有真正启用，只是把这条路先铺好。

## 六、诚实列出的待定事项

团队没有回避目前还没定下来的细节，而是明确列了出来，包括：登录状态能保持多久才需要重新登录、是否要上双重验证、换设备登录时的体验如何处理，以及短信验证码登录在被恶意高频尝试时该怎么限制。这些都是产品后续会继续打磨的方向，而不是被忽略的盲点。
