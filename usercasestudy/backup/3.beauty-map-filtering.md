# Beauty Map — Filtering

**Status:** v1 design. Filter dimensions for the map and list views.
Consumes `beauty-map-nearby-search.md` §2 (endpoint) and `beauty-map-postgis-schema.md`
§2 (cached columns). All filters compose with AND against the geo predicate.

## 1. Decisions

1. **Five dimensions in v1, no more.** Category, distance, rating, price, open-now.
   Each extra dimension multiplies test matrix; these five cover the real
   "find a place" jobs.
2. **Price filter is one-sided: `price_max_cents`.** Semantics: "cheapest bookable
   service ≤ X". A two-sided range over stores with $30–$200 menus creates
   range-overlap ambiguity nobody needs in v1; the real job is "find something
   affordable nearby".
3. **Distance is the geo mode itself, not a separate filter.** Bbox mode = viewport;
   radius mode = `radius_km`. No second distance param stacked on top.
4. **Filters never widen the geo result.** A filter can only remove stores, never add
   ones outside the viewport/radius — the map never lies about what's shown.
5. **Client-side clustering.** Mapbox GL JS clusters the GeoJSON source natively.
   No backend clustering work in v1; the 200-point cap keeps it smooth.

## 2. Filter parameters

| Param | Type | Semantics |
|---|---|---|
| `category` | slug | Store offers ≥1 active service in this category (categories from the service catalog) |
| `min_rating` | number | `avg_rating >= min_rating`; stores with no ratings are excluded when this is set (a 4.5+ filter shouldn't surface unrated stores) |
| `price_max_cents` | int | `price_from_cents <= price_max_cents` (cheapest bookable service within budget) |
| `open_now` | bool | `true` → only stores currently open (computed from `business_hours` in store tz) |

- All optional, AND-combined. Unknown category slug → `400 INVALID_CATEGORY`.
- `min_rating=0` is equivalent to unset (no filtering).

## 3. SQL composition

```sql
-- appended to the WHERE clause of beauty-map-nearby-search.md §3
AND (:category     IS NULL OR EXISTS (
      SELECT 1 FROM store.services sv
      JOIN store.service_categories sc ON sc.id = sv.category_id
      WHERE sv.store_id = s.id AND sv.status = 'active'
        AND sc.slug = :category))
AND (:min_rating   IS NULL OR (s.avg_rating IS NOT NULL AND s.avg_rating >= :min_rating))
AND (:price_max    IS NULL OR (s.price_from_cents IS NOT NULL AND s.price_from_cents <= :price_max))
AND (:open_now     IS NOT TRUE OR store.is_open_now(s.id))
```

- `store.is_open_now(store_id)`: helper reading `business_hours` in the store's
  timezone; returns false when hours are unset. Best effort, v1.
- The category `EXISTS` subquery is the only join in the hot path; at v1 volumes
  it's fine. If it ever shows in profiles, denormalize category slugs onto the store
  row.

## 4. UI contract (see `beauty-map-ui.md` page 2)

- The filter drawer shows all five dimensions; changing any of them re-issues the
  nearby request with the current viewport (debounced 300 ms on map move).
- Active filter count badge on the drawer button; one-tap "clear all".
- Empty result → "No stores match — try widening the map or clearing filters"
  (never a blank map with no explanation).

## 5. Test cases

1. `category=head-spa` → only stores with an active head-spa service.
2. `min_rating=4.5` → unrated stores excluded; 4.4 excluded; 4.5 included.
3. `price_max_cents=10000` → store with cheapest service $68 included; $120 excluded.
4. `open_now=true` at 3 AM → only 24h stores (or none), never a closed store.
5. All four combined → strictly fewer results than any subset.
6. Unknown `category=foo` → `400 INVALID_CATEGORY`.
