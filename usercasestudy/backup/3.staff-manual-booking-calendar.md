# Staff Manual Booking & Back-Office Calendar（2026-09-29 v1 草案）

本地 spec，供 Claude Code 实现。**只存本地，不上 GitHub。**

定位：店员/店长用的后台日历 + 手工建预约。创建走的**同一事务**（`create-appointment-transaction.md` §2.2 已定：`POST /api/store/appointments`，任何绕过 quota/double-booking 的手工路径都是 bug）——本篇定的是 UI 流程、列表接口、权限矩阵和日历交互，不再另发明创建逻辑。

基线事实：
- 状态机与取消/改期规则：transaction doc §1、§10。
- 通知：reminders doc（手工建的预约同样发确认短信）。
- slot 计算：slot engine；员工 UI 复用同一算法（调公开 `GET /api/store/public/slots` 即可，它本来就是无登录的）。
- 鉴权：`storeId ∈ caller.AuthorizedStoreIds`；跨店 404。

## 0. 本篇的裁决（先看结论）

1. **v1 日历交互 = 点选式，不做拖拽**。理由：拖拽的指针/触屏复杂度高；"点空位建预约、点预约看详情、Move 模式点新位置改期"覆盖全部工作流，拖拽是 v2 的体验优化。
2. **任何有本店 assignment 的 staff 都可以手工建预约**（可指派给店内任何可约员工）。理由：spa 前台就是接电话的员工在给所有技师约；建是低风险动作（事务兜底），改别人员工的预约才是高风险动作。
3. **改/取消/标 no-show/标完成：只能动自己的，或 store_admin/chain_admin 动全店/全连锁**。理由：与 item 7 矩阵的"own only"精神一致；前台建错了找店长改。
4. **no-show 只能标已开始的预约**（`now >= starts_at`）。理由：防手滑把未来的预约标了。
5. **v1 无需 schema 增量**——所有字段已存在。这篇是纯接口 + UI 流程文档。

## 1. 视图

| 视图 | 内容 | 默认 |
|---|---|---|
| Day（按员工列） | 每一列一个员工，当天的预约块；叠加显示该员工的 time off | staff 看自己；store_admin/chain_admin 看全店 |
| Week agenda | 按天列的列表，一周 | 全店（store_admin+），staff 看自己的一周 |
| Pending 队列 | `status='pending'` 待确认列表（`auto_confirm=false` 的店用） | 有 pending 才显示红点 |

- 时间轴粒度：沿用 `slot_granularity_minutes`。
- 每个预约块显示：时间、客户名、`service_summary`、状态色、🧪（is_test）、`reference_code` 后 4 位。
- Time off 以灰色块显示（只读；请假的增删改走 `staff-schedule-entry-workflow.md`，本篇不重复）。

## 2. 列表接口

`GET /api/store/appointments?store_id=&date=&staff_id=&status=` — `StoreSession`。

- `date`（`YYYY-MM-DD` 门店时区）与 `from`/`to` 二选一：day 视图用 `date`，week 用 `from`/`to`（最多 31 天，超了 400）。
- `staff_id` 可选；staff 身份调时**强制**只能查自己（传别人的 id → 404 口径）。
- `status` 可选，多值逗号分隔；不传 = 全部非终态？——v1 简单：不传返回全部状态，由前端分组；终态（cancelled/completed/no_show/expired）默认折叠显示。
- 返回：预约头 + items 快照 + 客户显示信息（`customer_id` 有则调客户档案取名字，无则 `guest_name`/`guest_phone`）+ `is_test`。

```json
{
  "date": "2026-10-05",
  "timezone": "America/Toronto",
  "appointments": [
    {
      "id": "uuid", "reference_code": "F7AE5724", "status": "confirmed",
      "staff_id": "uuid", "staff_name": "张技师",
      "starts_at": "2026-10-05T09:00:00", "ends_at": "2026-10-05T10:00:00",
      "customer_name": "李女士", "customer_phone": "416-123-4567",
      "is_test": false,
      "items": [{ "service_name": "深层清洁", "option_name": null,
                  "duration_minutes": 60, "price_cents": 8800 }]
    }
  ]
}
```

## 3. 日历动作接口（新增两个，别的沿用 transaction doc）

沿用（权限见 §4）：
- `POST /api/store/appointments/{id}/confirm`（pending→confirmed）
- `POST /api/store/appointments/{id}/cancel`
- `PATCH /api/store/appointments/{id}/reschedule`

新增：

| 方法与路径 | 说明 |
|---|---|
| `POST /api/store/appointments/{id}/no-show` | `confirmed → no_show`；要求 `now >= starts_at`，否则 `409 TOO_EARLY` |
| `POST /api/store/appointments/{id}/complete` | `confirmed → completed`（提前手动完成；sweeper 兜底超时） |

- 两个都是幂等：已经是目标状态 → 200 空操作。
- 都写 outbox 事件（`appointment.no_show` / `appointment.completed`，事件表在 transaction doc §11 基础上加两种类型）。

## 4. 权限矩阵

| 动作 | staff（本店） | store_admin（本店） | chain_admin（连锁） |
|---|---|---|---|
| 看日历 | 仅自己 | 全店 | 连锁内各店 |
| 手工建预约 | ✅（可指派给本店任何可约员工） | ✅ | ✅ |
| 确认 pending | 仅自己的 | 全店 | 全连锁 |
| 取消/改期 | 仅自己的 | 全店 | 全连锁 |
| 标 no-show / completed | 仅自己的 | 全店 | 全连锁 |
| 看客户电话 | 自己预约的 | 本店预约的 | 连锁内预约的 |

- 越权 → 404（沿用"不让状态码确认资源存在"口径）。
- `is_test` 的建/看：同上矩阵；test 预约在日历上永远带 🧪 标记，防和真实混淆。

## 5. 手工建预约流程（UI）

1. 日历点空位（或点"+ 新预约"）→ 弹窗表单。
2. 选服务（+option，如需）→ 选员工（默认当前视图的员工；staff 身份可改成店内其他人）→ 日期时间：**调 slots 接口取可选点**，下拉/点选（不允许手输任意时间，从根上消灭"约了个没空的时间"）。
3. 客户：搜现有客户（调客户档案搜索，deferred）或填 guest 姓名+电话。
4. `is_test` checkbox（仅员工端有；公开端永远 false）。
5. 提交 → `POST /api/store/appointments` → 同一事务（重校验/quota/幂等/出事件全在）。
6. 成功：日历上立即出现该块 + 按 reminders doc 发确认短信。

- 失败 `409 SLOT_TAKEN`：弹窗提示"这个时间刚被约走"，自动刷新该员工 slots 供重选。
- 失败 `409 QUOTA_EXHAUSTED`：免费版封顶，文案沿用 billing §4.3，引导联系 chain_admin 升级。

## 6. 改期交互（点选式 Move）

1. 点预约块 → 详情抽屉 → "改期"。
2. 进入 Move 模式：日历上该预约块半透明跟随（视觉），可切天/切员工。
3. 点目标空位 → 二次确认（显示 old → new）→ `PATCH .../reschedule`。
4. 成功：块落到新位置；失败 `409 SLOT_TAKEN` 留在 Move 模式供重选。

## 7. 显示规则

- 状态色：`confirmed` 蓝 / `pending` 琥珀（闪烁红点待确认）/ `cancelled` 灰（删除线）/ `no_show` 红 / `completed` 绿 / `expired` 灰 / `is_test` 一律加 🧪 角标。
- Pending 队列入口常驻顶栏，有未确认项时红点计数。
- 当天已过 `ends_at` 仍 `confirmed` 的（sweeper 还没跑）：显示为"待确认完成"，员工可手动点完成。

## 8. 测试用例

1. staff A 建预约指派给 staff B → 201；staff A 试图取消 staff B 的预约 → 404。
2. store_admin 取消 staff B 的预约 → 200。
3. 对 1 小时后的预约点 no-show → `409 TOO_EARLY`。
4. no-show 两次 → 第二次 200 空操作，只有一行 log。
5. Move 模式下目标 slot 被别人抢先 → `409 SLOT_TAKEN`，原预约不动。
6. 建预约时 quota 已满 → `409 QUOTA_EXHAUSTED`，日历无残留块。
7. `is_test` 预约：占 slot（公开 slots 查不到该时间）、不计 quota、日历有 🧪。
8. staff 传 `staff_id=别店的人` 建预约 → 404。
