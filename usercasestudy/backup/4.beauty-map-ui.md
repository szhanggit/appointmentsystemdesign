# Beauty Map — Map UI

**Status:** v1 design. The 5 customer/store pages. Data contracts come from
`beauty-map-nearby-search.md` §2.3 and `beauty-map-filtering.md` §2.
Booking itself is `public-booking-end-to-end-design.md` (`/book/{store_id}`) —
the map hands off, it doesn't reimplement.

Baseline: mobile-first, Mapbox GL JS, bilingual en/zh (same i18n framework as the
booking flow). One shared Groway map style in v1.

## 1. Decisions

1. **Map-first, list as secondary.** The v1 differentiator is the map; the list is a
   radius-mode rendering of the same API, not a separate product.
2. **Marker tap → preview card → detail page.** Two-step drill-down: the map stays
   uncluttered, the card answers "is this worth a tap", the page answers "book or not".
3. **Detail page reuses booking-flow components.** Service list, price display
   ("from $X" = live `MIN(options)`), staff picker — same components as
   `/book/{store_id}` Step 1–2, not copies.
4. **Store-side coordinate edit = autocomplete + draggable pin.** Address entry stays
   the Mapbox Search Box autocomplete already designed (`growayshop-registration-workflow.md`
   §2.2); this page only adds the pin fine-tune + save. One page, not two flows.
5. **No store photos in v1 map markers.** Custom marker images are a content-moderation
   problem; v1 markers are price/rating badges. Photo carousel lives on the detail
   page only if the store uploaded photos (V1.1 scope for uploads).

## 2. Page 1 — 地图主页 (customer)

- Full-screen Mapbox map, centered on customer location (browser geolocation, with
  graceful fallback to a default downtown-Toronto center when denied).
- Markers: clustered at low zoom (Mapbox GL JS native clustering on the GeoJSON
  source), individual pins at high zoom. Pin badge shows `price_from` ("$68+") or
  ★ rating — one badge mode, toggleable, default price.
- "Locate me" button re-centers. Map move (debounced 300 ms) re-queries bbox mode.
- Filter button with active-count badge → Page 2 drawer.
- Tap marker → Page 3 preview card (bottom sheet, map still visible behind).

## 3. Page 2 — 筛选抽屉 (customer)

- Bottom sheet with the 5 v1 dimensions (`beauty-map-filtering.md` §2):
  category chips, distance (radius-mode only — a slider 1–50 km; hidden in bbox mode
  where the viewport *is* the distance), min rating (Any / 4.0+ / 4.5+),
  max price (slider), open-now toggle.
- Apply-on-change (debounced), "Clear all" resets. Empty result → inline hint
  ("try widening the map or clearing filters"), never a dead blank map.

## 4. Page 3 — 店铺预览卡 (customer)

- Bottom sheet over the map: name, ★ `avg_rating` (`rating_count`), distance,
  `price_from`, open-now badge / "Opens 10 AM", `address_short`, category chips.
- Buttons: [查看详情] → Page 4. Swipe down dismisses.
- No booking action here — booking starts on the detail page, one consistent entry.

## 5. Page 4 — 店铺详情页 (customer)

- Header: name, rating, distance, address (tap → external maps app), phone (tap → call).
- Hours summary (today's hours + "see all" expander).
- Services grouped by category with live "from $X" pricing (shared component with
  booking Step 1).
- Rating summary only in v1 (no review writing — V1.1).
- Sticky bottom CTA: [预约] → `/book/{store_id}` (the public booking flow takes over).
- Unknown / inactive `store_id` → generic 404 ("Online booking isn't available for
  this store"), same rule as the booking flow.

## 6. Page 5 — 地址/坐标设置 (store side)

- Store settings section. Address field = the Mapbox Search Box autocomplete from
  `growayshop-registration-workflow.md` §2.2 (unchanged).
- Map with a draggable pin initialized at the geocoded position; dragging updates
  lat/lng; [Save] writes through the existing store-update endpoint → the
  `trg_stores_geo_sync` trigger rebuilds `geo` (`beauty-map-postgis-schema.md` §2).
- Save confirms with the resolved address + coordinates shown ("Pin set to
  8120 Bayview Ave — 43.8563, -79.3378").
