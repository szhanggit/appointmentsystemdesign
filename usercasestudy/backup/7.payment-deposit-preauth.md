# Payment: Deposit / Pre-auth（2026-09-29 v1 草案）

本地 spec，供 Claude Code 实现。**只存本地，不上 GitHub。**

定位：`booking_settings.payment_required=true` 的店，客户下单时在线付定金。收拢前文挂钩：transaction doc §12（`payment_required` 只建 pending，余下本篇定）、end-to-end §8（定金）。

基线事实：
- Provider 首选 **Stripe**（加拿大 2.9% + CA$0.30/笔国内卡，无月费；预授权/Apple Pay/Google Pay 原生支持）。
- 卡号永不经过 Groway 服务器（Stripe.js / Payment Element → PCI SAQ A）。
- 钱的 source of truth 是 Stripe；Groway 只存镜像 + 审计台账。
- 第三方费用由合伙人承担（已定），定金进**合伙人的 Stripe 账户**。

## 0. 本篇的裁决（先看结论）

1. **v1 = 下单时直接 capture 定金，不做预授权 hold**。理由：预授权 7 天过期，提前很久约的单 hold 会无声失效；直接扣定金无此问题，no-show 政策就是"定金不退"，少一个 capture 步骤。Pre-auth hold 是 v2（§11）。
2. **定金金额：店级配置，fixed 或 percent 二选一**。理由：spa 现实就是"$30 定金"或"50% 定金"两种。
3. **取消政策：免费窗口内取消自动退，窗口内/ no-show 定金不退**（`late_cancel_refund` 开关，默认 false）。理由：定金的意义就是 no-show 保护，默认关才有意义；结账页必须明示。
4. **Provider 抽象层 v1 就做**（`IPaymentProvider`），Stripe 是第一个实现。理由：以后按国家加方式（§3）不改 booking 代码。
5. **退款 v1 有店内按钮**（store_admin+），不让员工去 Stripe 后台。理由：审计台账要完整，绕过 Groway 的退款是黑洞。

## 1. 范围

v1 做：
- 公开下单的定金 capture（卡 / Apple Pay / Google Pay，经 Stripe）。
- 取消/改期的自动退与不退规则。
- 店内退款按钮 + 审计台账。
- Webhook 对账。

v1 不做：全额预付、店内刷卡机（Terminal）、分账（Connect）、预授权 hold（§11）、订阅/会员卡。

## 2. Provider 模型

```sql
-- 归属：store schema（钱跟着连锁走）
CREATE TABLE store.payment_provider_accounts (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  chain_id         UUID NOT NULL,              -- 一连锁一个 Stripe 账户
  provider_code    TEXT NOT NULL,              -- 'stripe'（以后 'alipay' 等）
  country          CHAR(2) NOT NULL,           -- 'CA'
  external_account_id TEXT NOT NULL,          -- Stripe account id (acct_...)
  credentials_ref  TEXT NOT NULL,              -- Vault 引用，不存明文 key
  status           TEXT NOT NULL DEFAULT 'pending',  -- pending/active/suspended
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (chain_id, provider_code)
);
```

- 开户是合伙人手动（Stripe KYC），开好把 account id 填进来，key 进 Vault。
- 代码侧：`IPaymentProvider` 接口（`create_payment`, `refund`, `get_status`）；`StripeProvider : IPaymentProvider`。
- 以后某国家要加本地方式：新增实现类 + `provider_code`，booking 流程不动。

## 3. 支付方式选择（三层）

1. **Provider × 国家给能力**：Stripe 在 CA 能开卡/Apple Pay/Google Pay；以后开新国家，能力清单从 provider 来。
2. **店主勾选**：`booking_settings.payment_methods_enabled[]`（如 `['card','apple_pay','google_pay']`），默认 = provider 在该国的推荐集。chain_admin 可关（如关掉分期类）。
3. **客户结账时自选**：Payment Element 把店主开的渲染成 tab，客户点一个。
4. 不是纯按国家自动（客户可能不信任某种方式），也不是无限制自选（店主管不住）。

## 4. 定金配置（`booking_settings` 新增）

| 字段 | 说明 |
|---|---|
| `payment_required` | 已有；true 才走本篇 |
| `deposit_type` | `'fixed'` \| `'percent'` |
| `deposit_fixed_cents` | fixed 时用，如 3000 = CA$30 |
| `deposit_percent` | percent 时用，如 50；按 items 快照总价算，四舍五入到分 |
| `late_cancel_refund` | 窗口内取消是否退定金，默认 `false` |
| `payment_methods_enabled` | §3 的勾选列表 |

- 定金 ≤ 订单总额；`free` 服务的单 `payment_required` 自动跳过（0 元不调 Stripe）。
- 结账页明示："定金 CA$X，开始前 Y 小时外取消自动退，Y 小时内取消/no-show 不退。"（Y = `cancel_threshold_hours`）

## 5. 下单流程（含支付）

`payment_required=true` 的公开下单：

```
1. POST /api/store/public/appointments（transaction doc §2.1）
   → 建单 pending，payment_status='awaiting'，占 slot（TTL 照旧）
   → 服务端建 Stripe PaymentIntent（amount=定金，idempotency key=appointment.id）
   → 返回 { appointment_id, client_secret, deposit_cents }
2. 前端 Payment Element 收卡 → stripe.confirmCardPayment(client_secret)
   → 客户在第 3 层里选方式（§3）
3. Webhook payment_intent.succeeded → payment_status='succeeded'
   → auto_confirm=true 则 confirmed，否则保持 pending（等店家确认）
   → 发确认短信（reminders doc 流程）
4. Webhook payment_intent.payment_failed / 15 分钟未付
   → 取消 PaymentIntent → 预约 expired → slot 释放（transaction doc §7 TTL）
```

- **前端回调成功 ≠ 成功**：一律以 webhook 为准；前端只做 UX 跳转。
- 金额服务端算（items 快照 → 定金），**不信任前端传的金额**。
- 改期不重新收钱（定金跟单走）；改期后总价变了定金不变——v1 规则，简单。

## 6. 取消 / no-show / 退款

| 场景 | 动作 |
|---|---|
| 免费窗口外取消 | 自动 refund（worker 监听 `appointment.cancelled` 事件） |
| 窗口内取消 | `late_cancel_refund=true` 才退，否则不退 |
| no-show | 定金不退（政策已在结账页明示） |
| completed | 无动作（定金抵扣尾款是店内 POS 的事，v1 不管） |
| 店内手动退款 | `POST /api/store/appointments/{id}/refund`（store_admin+），调 provider.refund，全额/部分（v1 只做全额） |

- 每次钱变动写 `store.payment_events`（append-only）：`appointment_id, provider_code, external_intent_id, type (capture/refund), amount_cents, status, webhook_id, created_at`。
- `appointments` 新增：`payment_status`（`none|awaiting|succeeded|failed|refunded|partially_refunded`）、`payment_intent_id`、`deposit_amount_cents`。

## 7. Webhook

- `POST /api/webhooks/stripe`（公开口，验签名 `Stripe-Signature`，不过直接 400）。
- 按 `event.id` 去重（`payment_events.webhook_id` 唯一约束顶掉重放）。
- 只处理白名单事件：`payment_intent.succeeded`、`payment_intent.payment_failed`、`charge.refunded`；别的记 log 不处理。
- Webhook 处理与预约状态机在**同一 DB 事务**里（状态 + 台账一起落，防"钱扣了单没确认"）。

## 8. 安全要点

1. Secret key 只在服务端 Vault；前端只有 publishable key。
2. 金额服务端算；PaymentIntent 金额与预约定金 double-check，不一致拒掉。
3. Webhook 验签名；客户端跳转不作为成功依据。
4. 退款接口限 store_admin+，且只能退本店的单。
5. 不存卡号、不存 CVV（本来也拿不到）。

## 9. 测试用例（Stripe test mode，全免费）

1. 下单 → 测试卡 `4242…` → webhook → `succeeded` → confirmed + 短信。
2. 测试卡 `4000…0002`（decline）→ `payment_failed` → 15 分钟后预约 expired，slot 释放。
3. Webhook 同一 event 发两遍 → 台账一行，状态机一次。
4. 前端传 `deposit_cents=1` 篡改 → 服务端按快照重算，不一致 400。
5. 免费窗口外取消 → 自动退款，`payment_events` 有 refund 行。
6. no-show → 定金保留，无 refund。
7. 未验签名的 webhook → 400，无状态变更。

## 10. 运营清单（给合伙人的 business 语言版要点）

- 定金进你的 Stripe 账户，2 个工作日左右到你银行卡。
- 每笔成本 2.9% + $0.30（$88 定金约 $2.85），从到账里直接扣。
- 退款：客人免费窗口外取消，系统自动退；你也可以在后台点退款。
- 对账：Stripe 后台 + Groway 台账两边都有。

## 11. 推迟（v2）

1. **Pre-auth hold**：下单只冻结、完成后 capture。v1 用直接扣简化掉 7 天过期问题。
2. 全额预付（不只是定金）。
3. Stripe Terminal（店内刷卡）。
4. Stripe Connect（多连锁分账/平台抽成）。
5. 新国家的新 provider（如支付宝/微信支付直连）。
6. 部分退款、定金转储值。
