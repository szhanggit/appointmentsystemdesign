Groway V1 — Staging 环境整体架构图

region: ca-central-1（多伦多）· 全部 Terraform 管理 · GitHub Actions CI/CD · 与 groway-v1-architecture.md 一致（EKS + KEDA，不是 ECS）
跟估算的对应关系（4 天搭建）：
  • 第 1 天：Terraform — VPC（公网/私网子网、NAT）、EKS 集群 + 节点组、IAM/IRSA。
  • 第 2 天：RDS PostgreSQL + PostGIS、ElastiCache Redis、SQS ×3 + DLQ、Secrets Manager。
  • 第 3 天：Cognito ×3（含 customer 池 Lambda triggers）、SNS/SES、CloudFront + S3、Route 53 + ACM 证书、ALB + Ingress。
  • 第 4 天：GitHub Actions（build → ECR → 部署 EKS）、冒烟测试、staging 域名联调。
Staging vs Production（差异就是那 10–15 天）：
  • Staging：单 AZ RDS、无 WAF、单 NAT、小节点组、日志保留短。只求"跑通"，不求"扛住"。
  • Production 另加：RDS Multi-AZ + 自动备份、WAF + Shield、CloudWatch 告警、SLO/值班、压测。
一个纠正：之前估算里我写了 ECS，以架构文档为准是 EKS（KEDA 需要 Kubernetes；应用本身仍是单个 Gateway 进程的 modular monolith，不拆微服务）。
